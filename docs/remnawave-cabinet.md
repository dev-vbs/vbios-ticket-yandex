# Возможности Remnawave в кабинете SHM

В карточке услуги категории `proxy` (или категории из `PROXY_CATEGORY`) появился раздел **«Ваша подписка под контролем»**. Стиль кабинета, AJAX-вход, импорт в приложение, QR-код и копирование ссылки сохранены.

| Раздел | Данные |
| --- | --- |
| Диагностика | Состояние услуги SHM и подписки Remnawave, срок, использованный трафик, остаток, стратегия и последний сброс |
| Серверы тарифа | Только `accessible-nodes` текущего пользователя; состояние сопоставляется с `/api/nodes` на сервере |
| Трафик | Последние 30 дней UTC, график и доступная таблица значений |
| Обновления | Последние запросы приложения на обновление подписки, без IP и внутренних правил |
| Расширения | Разовые платные услуги SHM: дополнительные устройства, трафик, internal squad |
| Действия | Отзыв ссылки с выдачей новой, сброс всех HWID; отдельное удаление остаётся в центре устройств |
| Уведомления | Окончание услуги, использование 80% лимита, новое устройство относительно предыдущей проверки |

Статус узла означает соединение узла с панелью. Он не заменяет измерение задержки с устройства клиента. История подписки не является историей сайтов или VPN-сеансов. Если API не сообщает дату следующего сброса, кабинет показывает стратегию и последний сброс, а не выдуманную дату.

## Подключение

1. Обновите **api, core и client** из одной сборки. Методы `Core::Remnawave::Cabinet` должны присутствовать и в API, и в обработчике локальных заданий.
2. Настройте [основной config.remna](remnawave-config-local.txt). `name_prefix` должен совпадать с именами уже созданных пользователей: например, `vBios_us_123`, где 123 — `user_service_id` SHM. Номер аккаунта из пользовательского storage больше не используется для выбора пользователя API.
3. `storage_prefix` в `config.remna` должен совпадать с `PROXY_STORAGE_PREFIX` клиента, особенно для замены ссылки.
4. Токен хранится только на сервере. Предоставьте ему доступ к пользователям, `accessible-nodes`, статистике, истории, HWID и revoke. `/api/nodes` нужен для состояния; без него локации показываются со статусом «Нет данных».
5. Для чтения действует кэш 20–30 секунд. Новые разделы загружаются при раскрытии, история и график — только при выборе соответствующей вкладки. Разные разделы отказывают независимо.

## Платные расширения

По умолчанию список пуст. Создайте в SHM **отдельные платные разовые услуги**: период 0, цена больше нуля, разрешён заказ, корректно настроен биллинг. Не используйте основные рекуррентные тарифы как расширения.

Перед включением расширений импортируйте [SQL-схему журнала выдачи](../server/app/sql/remnawave-addons.sql) в действующую базу SHM. Для compose-файла этого проекта, из корня репозитория:

```sh
docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" mysql -u "$MYSQL_USER" -D "$MYSQL_DATABASE"' < server/app/sql/remnawave-addons.sql
```

Для новой установки таблица включена в основную SQL-схему. До установки таблицы API запрещает создание заказа расширения.

Затем:

1. Создайте шаблон `Remnawave_Addon_LOCAL` из [готового файла](Remnawave_Addon_LOCAL.txt).
2. Привяжите его с транспортом **local** к событию активации после оплаты каждой дополнительной услуги. Не привязывайте его к событию создания неоплаченного заказа. Не заменяйте им основной шаблон создания пользователей Remnawave.
3. Сгенерируйте секрет: `openssl rand -hex 32`. Сохраните его резервную копию; изменение секрета делает подписи ранее созданных неоплаченных заказов недействительными.
4. Через административный транспорт **local** выполните [шаблон настройки расширений](remnawave-addons-config-local.txt), предварительно заменив секрет, `service_id`, разрешённые основные `tariff_ids` и UUID internal squad. Шаблон сохраняет существующие поля `config.remna`.
5. Проверьте на тестовом аккаунте: заказ без баланса → отсутствие расширения → оплата SHM → успешное локальное задание → изменение лимита → повтор того же задания без повторного начисления.

Клиент передаёт только ключ расширения и ID собственной основной услуги. Цена и объём берутся из серверной конфигурации и услуг SHM. При достаточном балансе стандартный биллинг SHM может оплатить заказ сразу. Пользователь получает ссылку на отдельную услугу для проверки и оплаты.

Обработчик проверяет владельца, фактическое списание SHM (`is_paid`), подпись неизменяемого снимка заказа и активность основной услуги. До запроса API сохраняется **абсолютный целевой лимит**, в отдельном журнале `remnawave_addon_ledger` через соединение с AutoCommit, а выполнение сериализуется MySQL `GET_LOCK` по основной услуге. Повтор после потери ответа API отправляет тот же лимит. Неопределённое задание блокирует следующие начисления для этой услуги до успешного повторного выполнения.

Если задание остановилось, **повторяйте то же задание**, не создавайте новую покупку. Не удаляйте незавершённые записи `remnawave_addon_ledger` и сохранённый `desired` вручную без сверки фактического лимита в панели. Если оплаченный заказ удалён администратором, требуется ручная сверка и возврат либо завершение выдачи.

Расширения разовые, без автопродления и автоматического возврата при блокировке. Устройства и локации рассчитаны на текущую основную услугу; при её продлении/смене тарифа основной provisioning-шаблон может восстановить базовые значения. Добавленный трафик увеличивает лимит подписки; правила его дальнейшего сброса и восстановления задаёт основной provisioning-шаблон. Это не отдельный несгораемый пакет. Согласуйте названия и описание услуг SHM с этими условиями, не обещайте автоматическое наследование расширений следующим тарифом.

При безлимитном трафике/устройствах соответствующее расширение не продаётся. Включение локации добавляет squad к текущему списку и не заменяет остальные локации. Настроенные расширения скрыты из обычного каталога. Прямая покупка через общий API заказа и смена основного тарифа на расширение запрещены. Это предотвращает создание оплаченного расширения без привязки к основной услуге. Административное ручное создание также не заменяет подписанный заказ из карточки.

## Ссылка доступа и устройства

Замена требует подтверждения и ограничена тремя запросами в сутки на услугу. После revoke старые URL в основном storage заменяются новой ссылкой. После неопределённого ответа клиент отдельно запрашивает текущую ссылку; операция revoke автоматически не повторяется. Сохраните настройки основного provisioning-шаблона так, чтобы он не восстанавливал старые ссылки из стороннего хранилища.

Сброс HWID не отзывает подписку: имеющее ссылку устройство может зарегистрироваться заново. При утечке используйте замену ссылки и при необходимости сброс привязок. Лимит устройств в центре берётся из фактического пользователя Remnawave, включая купленные расширения.

## Уведомления

На странице «Уведомления» и во вкладке диагностики выполняется проверка при открытии. Уведомления о новых устройствах сравнивают SHA-256 HWID с предыдущим снимком Redis. Первое посещение создаёт исходный список; событие показывается три дня, снимок хранится до 30 дней без посещений. Потеря Redis сбрасывает этот исходный список. Это не постоянный аудит подключений.

Это **уведомления внутри кабинета**, а не фоновая отправка Telegram/email. Переключатели действуют в текущем браузере. Серверные рассылки и периодические проверки требуют отдельной настройки событий/планировщика SHM.

## Проверка и выкладка

```sh
prove remnawave-operations-test.t remnawave-cabinet-test.t
cd client && npm ci && npm run build
```

Автотесты используют подмены транспорта и базы: проверяют границы доступа, фильтрацию данных, кэш, новые устройства, запрет неоплаченных/подменённых заказов, блокировку параллельных начислений и повтор после неопределённого ответа. Скриншоты используют демонстрационные данные. Работа с реальным SHM, его локальными заданиями, Remnawave и платёжной системой проверяется на вашем стенде перед продажами.

После успешной публикации образов в GitHub Actions:

```sh
docker compose pull api core client
docker compose up -d --no-deps --force-recreate api core client
docker compose ps api core client
docker compose logs --tail=100 api core client
```

Используйте имена сервисов из своего compose-файла, если они отличаются.
