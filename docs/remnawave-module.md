# Remnawave: серверный модуль SHM

[Клиентские функции, платные расширения и LOCAL-шаблоны](remnawave-cabinet.md).

Каталог из присланной OpenAPI содержит 218 операций. Исходная спецификация сохранена в `remnawave-openapi.yaml`, идентификаторы и маршруты — в `server/app/lib/Core/Remnawave/Operations.pm`.

Метод `operation` доступен только администратору SHM на сервере. Публичного HTTP-прокси полного API нет. Существующие клиентские методы HWID проверяют владельца услуги независимо от диспетчера.

1. Сохраните текущий `config.remna`: конфигурационный пример заменяет его целиком.
2. Замените домен и токен в `remnawave-config-local.txt`. Сохраните свои префиксы, иначе поиск существующих пользователей и подписок изменится.
3. Выполните этот шаблон транспортом `local` от администратора SHM.
4. Создайте шаблон `Remnawave_LOCAL` из `Remnawave_LOCAL.txt` и выполните его тем же транспортом от администратора.

Пример LOCAL выполняет только чтение узлов. Он не создаёт платные услуги и не заменяет действующие обработчики событий биллинга.

Вызов из Perl:

```perl
my $result = $remna->operation(
    operation_id => 'NodesController_getNodes',
);
```

Для маршрута с параметрами передайте `path_params => { uuid => '...' }`; параметры запроса — `query => { ... }`, JSON-тело — `body => { ... }`. Названия operationId, обязательные поля, схемы и методы берите из приложенной спецификации. Диспетчер подставляет URL-параметры с экранированием; JSON-тело проверяет Remnawave. Multipart и потоковые ответы требуют специализированного транспорта, этот JSON-диспетчер их не реализует.

Из шаблона параметры передаются аналогично:

```tt
{{ result = user.srv('Remnawave').operation(
    operation_id = 'NodesController_getNodes'
) }}
```

У задания LOCAL должен быть пользователь с правами администратора. Запуск от владельца обычной услуги завершится `Administrator required`. Не подменяйте пользователя задания администратором для шаблонов, содержимое которых может менять клиент.

Проверка после установки зависимостей сервера (из корня репозитория):

```sh
prove -v remnawave-operations-test.t
```

Тест не обращается к Remnawave: проверяет маршрутизацию, кодирование параметров, передачу тела и отказ обычному пользователю. Проверку реального домена и токена выполняет LOCAL-шаблон на вашем сервере.

Токены не выводятся LOCAL-примером. Не печатайте полный результат административных операций в публичных шаблонах: он может содержать приватные ссылки и настройки.

Присланный обработчик webhook не является LOCAL-шаблоном. Проверка только User-Agent не подтверждает подлинность отправителя. Не подключайте его к публичному endpoint без проверки секрета/подписи и защиты от повторной обработки. Автоматическая отправка Telegram-сообщений данным примером не выполняется.
