# Автоматическое завершение Reply после ответа

После успешной записи ответа бот отправляет подтверждение с remove_keyboard:true. Оно снимает ForceReply на поддерживающих это клиентах Telegram. Тикет остаётся открытым, переписка не удаляется. Для следующего ответа снова нажмите «Ответить» или используйте Reply на уведомлении. При ошибке сохранения подтверждение и снятие клавиатуры не отправляются. Стандартную панель цитаты Telegram обычно закрывает сам после отправки; принудительно управлять полем ввода на всех версиях клиента Bot API не позволяет.

Установка: этот комплект заменяет предыдущий ticket-telegram-reply-fixed, не устанавливайте оба последовательно. Выполните sudo bash /ПУТЬ/К/КОМПЛЕКТУ/install.sh на сервере; установщик рассчитан на /opt/shm и БД webface. После проверки закрепите Telegram.pm в исходниках и пересоберите образ. Инструкции предыдущей версии ниже.

# Исправленная версия: Telegram Reply и ForceReply

Исправлена подтверждённая ошибка Telegram «selective must be of type Boolean». Запрос теперь использует готовую JSON-строку {"force_reply":true}, selective убран. Добавлена подсказка в уведомление поддержки. Полный Telegram.pm входит в комплект, ручные Perl-замены не нужны.

Быстрая установка: распакуйте комплект НА СЕРВЕРЕ, затем выполните `sudo bash /ПУТЬ/К/КОМПЛЕКТУ/install.sh`. Скрипт рассчитан на /opt/shm, БД webface, сервисы core/mysql; запросит root-пароль MySQL. Если используется нестандартный набор Compose-файлов, задайте его в массиве COMPOSE перед запуском. Скрипт не меняет токены, конфигурацию ticket, ключи Yandex и TicketAI.pm. SQL только создаёт отсутствующие таблицы связей. Если они уже созданы, данные сохраняются.

Важно: полный Telegram.pm основан на присланном сервере 3.7.0. Если вы отдельно меняли другие функции транспорта после этой версии, сравните файлы перед заменой. Установка временно заменяет файл работающего core; для постоянной установки скопируйте app/lib/Core/Transport/Telegram.pm в исходники сервера и пересоберите образы core/spool вашим способом.

Проверено 13 условий с подставными БД/Telegram, включая JSON Boolean после сериализации. Реальная доставка на вашем сервере не выполнялась. Проверка синтаксиса с реальными зависимостями выполняется install.sh перед перезапуском, при ошибке восстанавливается предыдущий файл.

# Ответ пользователя на тикет через Telegram Reply

Обновление транспорта для присланного vbios 3.7.0. В группе поддержки сотрудник пишет в существующей теме тикета. Текст сохраняется в SHM, пользователь получает личное сообщение «Ответ поддержки по тикету #…» с кнопкой «Ответить». Можно нажать кнопку и ответить на запрос ForceReply либо воспользоваться обычным Telegram Reply на уведомлении. Ответ сохраняется в том же тикете и синхронизируется в группу. История отображается существующим кабинетом, изменения React не нужны.

Проверяется авторизованный владелец тикета; номер не извлекается из подделываемого текста цитаты. Сообщения связаны с тикетами через отдельную таблицу, закрытые обращения не принимают ответ. Повторная доставка одного Telegram-сообщения не создаёт второй ответ. После ответа сотрудника на этой ветке ИИ не запускается.

## Установка

Сохраните БД и текущий Telegram.pm. Обновление подготовлено на основе вашего архива 3.7.0; если после него вы отдельно меняли транспорт, сначала сравните изменения. Ticket.pm из Yandex-комплекта сохраняется.

Скопируйте содержимое app/ в исходники сервера. Примените SQL app/sql/ticket-telegram-reply.sql в существующую БД webface до запуска нового транспорта. Например, загрузите SQL в /opt/shm и выполните:

```bash
cd /opt/shm
docker compose cp ticket-telegram-reply.sql mysql:/tmp/ticket-telegram-reply.sql
docker compose exec mysql mysql -u root -p webface -e 'SOURCE /tmp/ticket-telegram-reply.sql;'
```

Для временной установки загрузите Telegram.pm в /opt/shm и выполните:

```bash
docker compose cp core:/app/lib/Core/Transport/Telegram.pm ./Telegram.pm.backup
docker compose cp ./Telegram.pm core:/app/lib/Core/Transport/Telegram.pm
docker compose exec core perl -I/app/lib -c /app/lib/Core/Transport/Telegram.pm
docker compose restart core
```

После syntax OK и проверки закрепите файл в исходниках и пересоберите core/spool вашим обычным способом. Временная замена внутри контейнера пропадёт при пересоздании. Если используете compose.ticket-storage.yml, команды сборки/запуска выполняйте с обоими -f, чтобы не вернуться на старый образ.

## Настройки

В config.ticket сохраняются существующие id группы, telegram_profile и forum_topics:1. Новых ключей или токенов не требуется. Группа должна быть форумом с темами; бот — администратор с правом управления темами. Сотрудники отвечают внутри соответствующей темы. В этой версии любое человеческое сообщение в настроенной теме трактуется как ответ поддержки: ограничьте состав группы доверенными сотрудниками.

Webhook должен принимать message и callback_query, быть настроен на тот же профиль, который связан с аккаунтом пользователя. Пользователь должен ранее запустить бота и не блокировать его. В config.telegram.server сохраняется ваш прокси, если прямой доступ к Telegram недоступен.

## Проверка

1. Создайте тестовый тикет в кабинете.
2. Ответьте от сотрудника в его теме группы.
3. У пользователя появится НОВОЕ уведомление с кнопкой «Ответить».
4. Нажмите кнопку и отправьте текст ответом на запрос бота. Проверьте историю кабинета и тему группы.
5. Повторите через обычный Reply на новом уведомлении поддержки.
6. Закройте тестовый тикет и попробуйте Reply: новый ответ сохраняться не должен.

Старые уведомления, отправленные до установки, не имеют серверной связи с тикетом. Reply на них не поддерживается; дождитесь нового ответа сотрудника. Никакое сообщение «тикет #…», набранное вручную, не создаёт такую связь.

Поддерживается текст. Фото/документы в этом Reply не загружаются в Yandex: бот предлагает приложить их через кабинет. Ответы самого ИИ этим обновлением в личный Telegram не пересылаются. Сообщения сотрудника, созданные сторонней админкой, также требуют отдельного вызова отправки: здесь обрабатываются ответы из темы группы.

При сетевом сбое сообщение может сохраниться в кабинете, но уведомление Telegram не доставиться; проверяйте telegram_error. Автоматическая очередь повторов исходящих сообщений не добавлена. Не пересылайте секреты, ссылки подписки и коды входа.
