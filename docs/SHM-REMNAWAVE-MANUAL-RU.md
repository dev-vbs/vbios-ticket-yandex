# Полный мануал: кабинет SHM, серверы и платные расширения

Этот мануал описывает настройку текущего проекта с нуля и добавление расширений в работающий кабинет. Названия пунктов админки могут отличаться между версиями SHM; рядом приведены точные имена полей.

**Главное:** деньги принимает и учитывает SHM. Remnawave получает команду изменить доступ только после подтверждения оплаченного заказа SHM.

## 1. Что подготовить

Нужны административные доступы к SHM и Remnawave, SSH к Docker-серверу и отдельный тестовый пользователь. Сохраните копии текущих config.main, config.remna, шаблонов и событий SHM. Все ID и цены ниже — **пример**, их нельзя считать значениями вашей базы.

Заполните рабочую таблицу:

| Что | Пример | Ваше значение |
| --- | --- | --- |
| Каталог compose на сервере | /opt/shm | |
| Основной тариф SHM: service_id | 10 | |
| Второй основной тариф (если есть) | 11 | |
| Активная услуга тестового пользователя: user_service_id | 123 | |
| Пользователь в Remnawave | vBios_us_123 | |
| URL Remnawave | https://panel.example.com | |
| Префикс имени пользователя | vBios_us_ | |
| Префикс storage | vpn_mrzb_ | |
| UUID Node «Москва» | UUID из Nodes | |
| UUID Node «Франкфурт» | UUID из Nodes | |
| UUID Internal Squad «Москва» | UUID группы | |
| UUID Internal Squad «Франкфурт» | UUID группы | |
| UUID отдельной платной группы | UUID группы | |
| service_id расширения устройств | 201 | |
| service_id расширения трафика | 202 | |
| service_id платной локации | 203 | |

`service_id` — ID тарифной записи. `user_service_id` — экземпляр услуги конкретного пользователя. Например, основная услуга №123 использует тариф №10: в tariff_ids пишется **10**, а не 123.

## 2. Обновление проекта

Дождитесь успешной сборки нужной версии в GitHub Actions. В каталоге вашего compose обновите связанные контейнеры одной версией:

```sh
cd /opt/shm
docker compose config --quiet
docker compose pull api core spool client
docker compose up -d api core spool client
docker compose ps
```

Если каталог другой — замените /opt/shm. Если ваша установка использует несколько compose-файлов, используйте тот же набор -f, с которым она запускается. Рабочий процесс очереди называется **spool** в compose этого проекта; его тоже нужно обновить, иначе оплата будет проходить через новый API, а выдача — через старый модуль.

Файлы docs и SQL на сервере должны соответствовать этой же версии проекта. Не выполняйте git pull поверх неизвестных локальных изменений без их сохранения.

## 3. Настройка Remnawave

### 3.1. Узлы, профили и hosts

1. Убедитесь, что узлы подключены к панели и не выключены.
2. Подготовьте inbound-профили и hosts для каждого сервера по правилам вашей версии Remnawave.
3. Создайте отдельные Internal Squads для Москвы и Франкфурта. В каждую включите inbound-профили нужного сервера.
4. Для платной локации создайте **другую** Internal Squad, которая не входит в бесплатные варианты переключения.
5. Сохраните UUID узлов и UUID групп отдельно.

Права Remnawave назначаются через группы, а не через UUID Node. Общая группа с профилями всех серверов откроет все эти серверы. Чтобы подписка меняла одну локацию, группы должны соответствовать отдельным локациям; общая неуправляемая группа пользователя также не должна открывать их все.

Кабинет при переключении заменяет только группы из server_choices текущего тарифа. Остальные группы сохраняются, включая платную локацию. Группа платной локации не должна одновременно входить в server_choices.

### 3.2. API и тестовый пользователь

Создайте API-токен панели с доступом к используемым методам: получение/изменение пользователя, accessible-nodes, nodes, статистика трафика, история подписки, HWID и отзыв ссылки. Точный набор прав зависит от вашей версии панели.

Проверьте имя пользователя, которого создал основной шаблон SHM. Для услуги №123 и name_prefix = 'vBios_us_' модуль ищет **vBios_us_123**. Префикс нельзя произвольно менять для уже работающих пользователей.

Для проверки расширений задайте тестовому пользователю **конечные** лимиты, например 3 устройства и 100 ГБ. Нулевой лимит означает безлимит: покупать увеличение такого лимита не требуется. Значение по умолчанию в config.remna не переписывает лимиты существующих пользователей панели.

## 4. Основной тариф SHM

Основной тариф должен создавать обычную подписку и сохранять ссылку в SHM. Существующий рабочий шаблон создания подписки сохраняйте: обработчик расширения его не заменяет.

Проверьте:

| Поле | Значение |
| --- | --- |
| service_id | Реальный ID основного тарифа, например 10 |
| category | Категория, распознаваемая как proxy/Remnawave |
| allow_to_order | 1, если тариф должен продаваться |
| Стоимость и период | Ваши реальные условия основного тарифа |
| Основные события/шаблоны | Уже настроенное создание и управление подпиской |

Не переводите основной тариф в категорию расширений. У тестового пользователя услуга должна быть **ACTIVE**, а подписка Remnawave должна существовать.

## 5. Создание услуг расширений

Откройте раздел тарифных услуг SHM и создайте три **отдельные простые услуги**, не дочерние копии основного тарифа. Для них используйте отдельную категорию **remna_addon**.

| Поле | Устройства | Трафик | Локация |
| --- | --- | --- | --- |
| Название | Ещё 2 устройства | Ещё 50 ГБ | Дополнительная локация |
| Пример цены | 50 ₽ | 100 ₽ | 150 ₽ |
| period | 0 | 0 | 0 |
| category | remna_addon | remna_addon | remna_addon |
| allow_to_order | 1 | 1 | 1 |
| pay_in_credit | 0 | 0 | 0 |
| is_composite | 0 | 0 | 0 |
| config | JSON ниже | JSON ниже | JSON ниже |

В поле **config каждой услуги** добавьте, сохранив другие необходимые параметры:

```json
{
  "no_auto_renew": 1
}
```

Это разовая покупка. Период 0 сам по себе не заменяет запрет автопродления: в биллинге такого заказа нужно явно исключить повторное автоматическое списание. Не включайте order_only_once, если пользователь должен иметь возможность купить ещё одно расширение позднее.

Если скидки и бонусы не должны менять цену, настройте соответствующую политику SHM (например no_discount для запрета скидки). Итоговое списание определяет SHM, а карточка расширения показывает базовую цену услуги.

Сохраните и запишите фактически выданные service_id. SHM может присвоить **другие ID**, а не 201/202/203. В конфиге затем укажите реальные значения.

Не выдавайте этим услугам обычные события создания/удаления пользователя Remnawave. События расширений должны вызывать только обработчик расширения, отфильтрованный по отдельной категории. Проверьте также существующие широкие правила category = "%": они могут запускаться для новых услуг дополнительно.

После регистрации ID в config.remna.addons услуги скрываются из обычного каталога кабинета. Покупка выполняется из карточки **основной услуги → Расширения**, чтобы заказ получил защищённую привязку к этой услуге. Ручной заказ из админки без такой привязки не заменяет этот сценарий.

## 6. SQL-журнал

Журнал обеспечивает повтор выдачи без двойного начисления. Для новой установки он включён в актуальную схему. Для существующей базы импортируйте из корня репозитория:

```sh
docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" mysql -u "$MYSQL_USER" -D "$MYSQL_DATABASE"' < server/app/sql/remnawave-addons.sql
```

Команда использует пароль контейнера MySQL и не требует вставлять его в историю команд. Путь справа — файл на сервере, где вы запускаете docker compose; при другом каталоге используйте полный путь. Файл содержит CREATE TABLE IF NOT EXISTS.

Проверка наличия таблицы:

```sh
docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" mysql -u "$MYSQL_USER" -D "$MYSQL_DATABASE" -e "SHOW TABLES;"'
```

В списке должна присутствовать remnawave_addon_ledger. Также можно выполнить SHOW TABLES LIKE 'remnawave_addon_ledger'; в SQL-консоли администратора. Не редактируйте записи незавершённых выдач вручную.

## 7. Шаблон выдачи

В разделе шаблонов SHM создайте запись с ID/именем **Remnawave_Addon_LOCAL**. Вставьте содержимое [готового файла](Remnawave_Addon_LOCAL.txt):

```text
{{ result = user.srv('Remnawave').fulfill_addon(order_id = us.id) }}
{{ IF result.ok }}
{{ r = task.answer(status = SUCCESS) }}
Расширение применено.
{{ ELSE }}
{{ r = task.answer(status = FAIL) }}
Расширение не подтверждено. Проверьте журнал задания перед повторной покупкой.
{{ END }}
```

Это обработчик задания, а не самостоятельный конфиг. Не запускайте его вручную без контекста оплаченного заказа. `us.id` здесь — ID **заказа расширения**, не основной услуги. Основная услуга определяется из подписанного снимка заказа.

Модуль дополнительно проверяет is_paid SHM. Одного статуса ACTIVE или вручную выставленного SUCCESS недостаточно для подтверждения оплаты.

## 8. События CREATE и ACTIVATE

**Исправление прежней краткой инструкции:** привязки только к ACTIVATE недостаточно. В этом проекте Core::Billing::create сначала вызывает is_pay, а при успехе возвращает CREATE. Новая неоплаченная услуга получает NOT_ENOUGH_MONEY. Поэтому CREATE здесь — биллинговое событие успешного создания после оплаты, а не сам факт добавления записи заказа.

В разделе событий SHM создайте **два правила**, общих для категории remna_addon:

| Поле события | Первое правило | Второе правило |
| --- | --- | --- |
| kind | UserService | UserService |
| title | Выдать оплаченное расширение | Выдать расширение после активации |
| name | CREATE | ACTIVATE |
| server_gid | 0 / без группы серверов | 0 / без группы серверов |
| settings | JSON ниже | Тот же JSON |

```json
{
  "category": "remna_addon",
  "transport": "local",
  "template_id": "Remnawave_Addon_LOCAL"
}
```

Здесь **category — строка**, не массив и не service_id. Транспорт тоже должен быть local. ID шаблона — его строковое имя Remnawave_Addon_LOCAL. Этот вариант не требует группы серверов для локального выполнения.

Если интерфейс показывает category/transport/template_id отдельными полями, задайте те же значения через него. Не создавайте дополнительные дубли тех же правил. Проверьте, что обработчик не назначен на NOT_ENOUGH_MONEY, PROLONGATE, BLOCK, REMOVE или CHANGED. Регулярное продление не должно быть механизмом выдачи разовой покупки.

Оба платёжных маршрута могут встретиться в зависимости от состояния услуги и обработки очереди. Повтор одного и того же заказа защищён журналом, но дубли событий всё равно следует устранить.

## 9. Полный конфиг local

Откройте [полный шаблон](cabinet-full-config-local.txt). Измените объект settings в самом начале:

```text
panel_url = 'https://ВАША-ПАНЕЛЬ'
api_token = 'ВАШ_API_ТОКЕН'
name_prefix = 'vBios_us_'
storage_prefix = 'vpn_mrzb_'
tariff_ids = [10, 11]
addon_devices_id = 201
addon_traffic_id = 202
addon_location_id = 203
```

Подставьте ID из вашей рабочей таблицы. Если основной тариф один, используйте, например tariff_ids = [10]. Добавьте реальные UUID Node для мониторинга и UUID Internal Squad для локаций.

Сгенерируйте signing_key на сервере:

```sh
openssl rand -hex 32
```

Вставьте результат как строку в settings.signing_key. Генерируйте один раз; при последующих применениях используйте прежний ключ. Он не должен попадать в config.main, клиентский env, GitHub или скриншоты.

В SHM создайте административный шаблон **Cabinet_FULL_LOCAL**, вставьте отредактированный полный файл и выполните через транспорт local. Шаблон задаёт:

- config.main: тексты, блоки стартовой страницы и мониторинг;
- config.remna: адрес/токен, префиксы, server_choices, addons и ключ подписи.

Существующие неуказанные поля сохраняются. Перечисленные тексты, списки выбора и расширений обновляются. При повторном применении проверьте все значения: конфиг не должен вернуть старые ID или секрет. Полный порядок настройки окружения также есть в [справочнике полного конфига](cabinet-full-config.md).

Если уже настроен сайт и нужны только расширения, используйте [отдельный шаблон addons](remnawave-addons-config-local.txt), сохранив действующий ключ подписи и реальные ID. Если нужен только выбор серверов — [шаблон server_choices](remnawave-servers-config-local.txt). Эти варианты не требуют повторно менять тексты сайта.

## 10. Настройки клиента

Полный список публичных переменных: [cabinet-client.env.example](cabinet-client.env.example). Подключение через env_file и приоритет compose environment описаны в [полном конфиге](cabinet-full-config.md#4-настройте-docker-клиент).

Основная категория тарифа должна распознаваться как Remnawave/proxy, например:

```dotenv
PROXY_CATEGORY=proxy,vpn-mz,vpn-promo
PROXY_STORAGE_PREFIX=vpn_mrzb_
SHOW_PROXY_SUB_LINK=true
SHOW_PROXY_QR=true
```

Не добавляйте remna_addon в PROXY_CATEGORY: у заказа расширения нет отдельной подписки, устройств и серверов.

После изменения переменных контейнера:

```sh
docker compose config --quiet
docker compose up -d --no-deps --force-recreate client
```

После изменения config.main/remna обновите страницу, учитывая кэш данных до 30 секунд. Если обновлялись образы, обновите api/core/spool/client вместе.

## 11. Проверка покупки

Сначала проверяйте на тестовом аккаунте, не на платящем клиенте.

### Проверка устройств

1. Основная услуга ACTIVE, лимит пользователя панели — 3 устройства.
2. Откройте основную услугу в кабинете → «Ваша подписка под контролем» → «Расширения».
3. Нажмите «Добавить» у +2 устройств и подтвердите один раз.
4. При недостаточном балансе должен появиться заказ SHM, а лимит панели должен остаться 3.
5. Пополните баланс через SHM и дождитесь обработки заказа.
6. Проверьте задание CREATE/ACTIVATE с шаблоном Remnawave_Addon_LOCAL и его результат.
7. После успешной выдачи лимит панели должен стать **5**, а журнал — показать applied = 1.
8. Повторите то же задание через штатный механизм очереди на тестовом аккаунте: лимит должен остаться 5. Это проверка идемпотентности, не новая покупка.

Если денег хватает в момент оформления, SHM может списать их сразу. «Оплачен» в кабинете означает оплату SHM; изменение лимита происходит после успешного задания spool.

### Проверка трафика

При исходном лимите 100 ГиБ и добавлении 53687091200 байт новый лимит — 150 ГиБ. Счётчик уже использованного трафика не сбрасывается. При использованных 20 ГиБ остаток увеличится со 80 до 130 ГиБ, а не станет 150. В интерфейсе единицы подписаны «ГБ», расчёт использует 1024³ байт.

### Проверка локации

До покупки пользователь не должен состоять в платной Internal Squad. После оплаты и выдачи она добавляется к текущим группам без удаления остальных. Обновите подписку в приложении и проверьте появление hosts этой группы. Затем переключите бесплатную локацию в кабинете: платная группа должна сохраниться.

## 12. Добавление нового расширения

Пример: хотите продавать ещё 1 устройство дополнительно к варианту +2.

1. Создайте новую простую услугу SHM: название, ваша цена, period = 0, category = remna_addon, allow_to_order = 1, config.no_auto_renew = 1.
2. Запишите выданный service_id, например 204.
3. В действующий массив config.remna.addons добавьте **новый объект**, сохранив остальные:

```text
{
    key = 'devices_1'
    title = 'Ещё 1 устройство до окончания услуги'
    service_id = 204
    tariff_ids = [10, 11]
    type = 'devices'
    amount = 1
}
```

4. key должен быть уникальным. Цена не добавляется в этот объект — она берётся из услуги 204 в SHM.
5. Новые события создавать не нужно, если существующие CREATE/ACTIVATE уже обслуживают категорию remna_addon. Убедитесь, что новая услуга использует эту категорию.
6. Примените изменённый конфиг с прежним addon_signing_key и проверьте новую покупку на тестовом аккаунте.

Другие типы:

| type | Обязательные параметры | Что изменяет |
| --- | --- | --- |
| devices | amount — целое число устройств | hwidDeviceLimit |
| traffic | amount — целое число байт | trafficLimitBytes |
| locations | squad_uuid — UUID Internal Squad | Добавляет группу к activeInternalSquads |

Например, 10 ГиБ = 10737418240 байт; 50 ГиБ = 53687091200; 100 ГиБ = 107374182400. Для location amount не используется. Для devices/traffic squad_uuid не используется.

Не редактируйте снимок уже созданного заказа: условия в нём подписаны. Новые настройки относятся к новым заказам; существующие выдаются по сохранённому снимку.

## 13. Ошибки и восстановление

| Симптом | Что проверить |
| --- | --- |
| «Выбор локации для этого тарифа ещё не настроен» | config.remna.server_choices не пуст; тариф основной услуги входит в tariff_ids; server_choice_enabled = 1 при применении полного шаблона; API обновлён |
| «Расширения пока не настроены» | config.remna.addons, реальные tariff_ids, addons_enabled = 1 |
| Карточка говорит про разовый тариф | Услуга расширения должна иметь period = 0, не период основного тарифа |
| Заказ запрещён | allow_to_order = 1 и услуга разрешена действующим прайс-листом SHM для пользователя |
| Карточка говорит про безлимит | В панели лимит 0 или не задан; для теста задайте конечный лимит |
| Ошибка ключа подписи | Реальная строка из openssl rand -hex 32; не заглушка; тот же ключ в API и spool |
| Не установлен журнал | Импорт SQL в ту базу, с которой работают api и spool |
| Оплата прошла, задания нет | CREATE настроен, не только ACTIVATE; settings.category — строка remna_addon; сервис расширения в этой категории; нет конфликтующих широких правил |
| Задание не находит шаблон | ID шаблона точно Remnawave_Addon_LOCAL и settings.template_id совпадает |
| Задание пишет Payment required | Нужен оплаченный заказ SHM с фактической датой списания; не подменяйте это ручным статусом |
| Задание пишет Not an addon order | Услуга создана вручную или через общий заказ без защищённой привязки; покупка должна начинаться во вкладке расширений основной услуги |
| Пользователь панели не найден | name_prefix + ID основной услуги совпадают с username; нет переопределения url/api_token/name_prefix на сервере SHM |
| Смена сервера отклоняется | Нет пересечения платной группы с бесплатными; основная услуга ACTIVE; нет незавершённой выдачи расширения |
| После оплаты сумма списывается повторно | Проверьте config.no_auto_renew = 1 у разового тарифа и отсутствие новых покупок/ручных перепроведений; сравните ID заказов и списаний |
| Лимит изменился, приложение не видит локацию | Обновите подписку в приложении, проверьте hosts и профили squad в Remnawave |

Логи Docker:

```sh
docker compose ps api core spool client
docker compose logs --tail=100 api spool
```

В админке SHM найдите заказ расширения, его списание и задания очереди. Не публикуйте полные логи, если в них есть токены или ссылки доступа.

Для администратора базы полезны **только читающие** запросы. Замените примерные ID:

```sql
SELECT service_id, name, cost, period, category, allow_to_order,
       JSON_EXTRACT(config, '$.no_auto_renew') AS no_auto_renew
FROM services WHERE service_id IN (201, 202, 203);

SELECT id, name, kind, server_gid, settings
FROM events
WHERE JSON_UNQUOTE(JSON_EXTRACT(settings, '$.category')) = 'remna_addon';

SELECT order_id, user_id, target_id, applied, applied_at
FROM remnawave_addon_ledger WHERE order_id = 456;
```

`applied = 1` — выдача зафиксирована. `applied = 0` — незавершённая выдача; отсутствие записи может означать, что задание ещё не дошло до изменения API. Сверьте состояние панели и журнала задания. Не ставьте applied = 1 вручную, не удаляйте pending-запись и не меняйте desired.

Если API изменил лимит, но ответ потерялся, повторяйте **тот же заказ/задание**. Сохранённый целевой лимит предотвращает повторное начисление. Новая покупка — новый оплачиваемый заказ. Возврат при невозможности выдачи делается по вашей процедуре SHM; автоматического возврата в модуле нет.

## 14. Ограничения и проверка перед продажами

Расширения меняют параметры текущего пользователя Remnawave. Они не меняют основной рекуррентный тариф SHM. Наследование при продлении, пересоздании пользователя и смене тарифа зависит от вашего основного шаблона выдачи и не гарантируется модулем автоматически. Не обещайте срок действия, который ваш шаблон не поддерживает; отдельно проверьте продление и сброс лимита трафика.

Включите продажи после проверки на стенде:

- новая оплаченная покупка через CREATE и покупка после недостатка средств;
- отсутствие выдачи без оплаты;
- успешная выдача устройств, трафика и отдельной группы;
- повтор того же задания без двойного начисления;
- разовый заказ без автопродления и повторных списаний;
- сохранение купленных групп при переключении локации;
- корректное поведение основного шаблона при продлении;
- понятные условия, цены, порядок поддержки и возвратов.

Мануал сверён с кодом этого репозитория, но не заменяет проверку вашей базы, событий, прав токена и платёжного провайдера на действующей установке.
