# Обновление защиты и страницы входа

Обновление ограничивает выбор CGI разрешёнными каталогами, закрывает обход
OTP через Basic/старый вход, проверяет разрешения старых диагностических CGI
и защищает OAuth/Telegram-привязку одноразовым состоянием и cookie браузера.
Страница входа сохраняет пароль, OTP, passkey, Telegram, регистрацию и восстановление.

## Установка

1. Сделайте резервную копию БД и конфигурации.
2. Дождитесь успешного workflow **Build and publish vBios images** для нужного коммита.
3. Обновите контейнеры:

   ```bash
   cd /opt/shm
   docker compose pull api core spool client
   docker compose up -d api core spool client
   ```

4. Примените настройки внешнего Nginx из
   [примера](new-server/nginx-vbios.conf.example), заменив домены и пути сертификатов.
   Особенно важно передавать `X-Forwarded-For $remote_addr`, а не добавлять
   предоставленную посетителем цепочку. Проверьте `nginx -t` перед reload.
5. Проверьте обычный вход, OTP, Telegram-вход и привязку из профиля,
   отправку тикета и фотографии в обе стороны.

Миграция БД для этого обновления не нужна. Обновление образов не меняет
конфигурацию Nginx на хосте автоматически.

## Совместимость

- Используйте кабинет и его API на одном HTTPS-домене через `/shm/v1`.
  Непроверенные Origin отклоняются. При необходимости отдельных доверенных
  клиентов задайте `CORS_ALLOWED_ORIGINS` в окружении **core** точным списком
  origins через запятую (без завершающего слеша). Это разрешение доступа,
  не способ отключить защиту; не добавляйте посторонние домены.
- Cookie сессии использует HttpOnly и SameSite=Lax; OAuth/OIDC запускается
  через штатный init/start на том же домене. Старые незавершённые попытки
  входа следует начать заново после обновления.
- Callback принимает параметры привязки и PKCE только из серверного состояния.
  Произвольные `return_url`, собственные callback URI и вход по одному
  `id_token` без предварительного init больше не поддерживаются.
- Старый Telegram Widget может привязывать аккаунт только с явно переданной
  действующей сессией, не с одной ambient cookie.
- Basic/header-вход для аккаунтов с OTP или отключённым паролем запрещён.
  Для автоматизации используйте предусмотренные API-токены.
- OAuth проверяет сохранённый subject провайдера. Старые связи без subject
  требуют повторной привязки из уже авторизованного профиля.
- Диагностика SSH/почты требует разрешения на изменение
  `/admin/legacy/ssh_test.cgi` и `/admin/legacy/mail_test.cgi`;
  разрешения только на чтение недостаточно.
- Не публикуйте порты client/admin/phpMyAdmin напрямую в Интернет.
  Контейнерные прокси доверяют приватной сети; внешний HTTPS-прокси обязан
  перезаписывать входящие forwarding-заголовки.

## Что остаётся за администратором

Замените ранее опубликованные токены Telegram, ключи AI/S3 и пароли БД.
Изменение пароля существующей MySQL только в .env не меняет его в самой БД:
сначала обновите пользователя MySQL, затем согласованно окружение приложений.
Ограничьте IAM приватным бакетом, включите OTP администраторам и храните
резервные копии отдельно от сервера.

Проверка исходников была частичной. Образы сторонней админки, зависимости и
реальная инфраструктура не прошли полный аудит; это обновление не является
гарантией отсутствия других уязвимостей.
