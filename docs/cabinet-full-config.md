# Полная настройка кабинета SHM и Remnawave

Начните с [единого шаблона local](cabinet-full-config-local.txt). Он настраивает содержимое сайта, публичный мониторинг, приватное подключение Remnawave, выбор серверов и три вида платных расширений. Он не создаёт тарифы, платёжные системы, узлы, группы и события SHM: эти сущности должны существовать. Платежи и списания выполняет SHM.

## 1. Подготовьте значения

Сохраните резервные копии текущих config.main и config.remna. В начале шаблона измените объект settings:

| Поле | Откуда взять |
| --- | --- |
| panel_url | HTTPS-адрес панели Remnawave без завершающего / |
| api_token | Токен API панели; хранить только в config.remna |
| name_prefix | Префикс имени уже созданных пользователей панели: для vBios_us_123 это vBios_us_. Не меняйте на работающей установке без миграции |
| storage_prefix | Префикс хранилища ссылок SHM; должен совпадать с PROXY_STORAGE_PREFIX клиента и шаблоном создания подписки |
| tariff_ids | service_id основных тарифов SHM. Замените пример [10, 11] на реальные ID, например [7]. Это НЕ user_service_id и НЕ ID пользователя |
| node_moscow, node_frankfurt | UUID узлов из раздела Nodes панели; используются только в мониторинге |
| squad_moscow, squad_frankfurt | UUID отдельных Internal Squads для бесплатного переключения; каждая группа должна включать inbound-профили нужного сервера |
| squad_paid | UUID отдельной платной Internal Squad, не совпадающий с группами бесплатного выбора |
| addon_devices_id, addon_traffic_id, addon_location_id | ID отдельных услуг SHM с периодом 0, ценой больше нуля и разрешённым заказом. Примерные 201/202/203 заменить |
| signing_key | Результат openssl rand -hex 32. Если уже настроен — используйте существующий ключ, не генерируйте новый для каждого применения |
| monitor_enabled, server_choice_enabled, addons_enabled | 1 включает соответствующий раздел, 0 отключает. Отключение выбора/расширений очищает их настроенные списки |

Группы и UUID узлов — разные значения. UUID узла в squad_uuids не выдаёт права подключения. Настройте hosts и профили в панели; одна общая группа со всеми узлами не ограничит подписку одним сервером. Переключение заменяет только группы перечисленных вариантов текущего тарифа, остальные сохраняются.

Для устройства и трафика 0 в панели означает безлимит: такие расширения не продаются. Чтобы проверить покупку, тестовый пользователь должен иметь конечный лимит, например 3 устройства и 100 ГБ. Поле hwidDeviceLimit в config.remna само по себе не меняет лимит существующего пользователя Remnawave.

Пример генерации секрета на сервере:

```sh
openssl rand -hex 32
```

Секрет не публикуйте в config.main, клиентском env, скриншотах или GitHub. При обновлении используйте прежний секрет, чтобы не сломать подписи существующих заказов.

## 2. Настройте услуги и выдачу расширений

Обновите api, core и client одной версией проекта. Для действующей базы импортируйте журнал выдачи **один раз**, из корня репозитория:

```sh
docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" mysql -u "$MYSQL_USER" -D "$MYSQL_DATABASE"' < server/app/sql/remnawave-addons.sql
```

SQL использует CREATE TABLE IF NOT EXISTS. В новой базе из актуальной схемы таблица уже присутствует. Если каталог репозитория не является каталогом запуска compose, используйте полный путь к SQL-файлу.

Создайте шаблон **Remnawave_Addon_LOCAL** из [готового обработчика](Remnawave_Addon_LOCAL.txt). У каждой из трёх дополнительных услуг привяжите этот шаблон с транспортом **local** к событиям CREATE и ACTIVATE отдельной категории remna_addon. CREATE в этом биллинге следует после успешной оплаты; только ACTIVATE недостаточно. Не назначайте выдачу на NOT_ENOUGH_MONEY. Основной обработчик создания подписки не заменяйте: он по-прежнему создаёт пользователя Remnawave и сохраняет ссылку в SHM.

Цены задаются в услугах SHM, не в config.remna. Стоимость витрины plans в config.main — только текст; сейчас в полном шаблоне plans = [], чтобы не показывать выдуманные цены. Добавляйте реальные значения после настройки тарифов.

## 3. Примените полный шаблон

В административной части SHM создайте шаблон **Cabinet_FULL_LOCAL**, вставьте целиком отредактированный [файл](cabinet-full-config-local.txt), выберите транспорт **local** и выполните от администратора.

Проверки незаменённых заглушек выполняются до записи. Перед сохранением проверьте примерные числовые ID вручную — шаблон не знает ID вашей базы. Остальные существующие поля main/remna сохраняются; перечисленные в шаблоне поля, массивы и тексты обновляются. При включённых расширениях ключ подписи берётся из settings.signing_key.

config.main публичный: там только тексты и UUID публичного мониторинга. URL API, токен и ключ подписи находятся в config.remna. Результат выполнения их не выводит. Обновите страницу кабинета после применения. Статистика кэшируется до 30 секунд, публичный мониторинг — 15 секунд.

Если config.remna содержит специфичные для вашей установки internal_squads, external_squad, time_zone или лимиты, шаблон сохраняет их. Если этих полей нет, создаются значения по умолчанию. Настройки конкретного сервера SHM url/api_token/name_prefix имеют приоритет над глобальными: проверьте их, если запросы идут в другую панель.

## 4. Настройте Docker-клиент

[Полный пример публичных клиентских параметров](cabinet-client.env.example) содержит название, категории, префиксы хранилища, способы входа, юридические ссылки, политику заказов и ссылки на приложения. Это отдельные настройки; в config.main их переносить нельзя. Не включайте авторизацию, требующую серверной настройки, пока не настроены соответствующие методы SHM.

Скопируйте файл как cabinet-client.env рядом с docker-compose.yml, измените значения и подключите в docker-compose.override.yml:

```yaml
services:
  client:
    env_file:
      - ./cabinet-client.env
```

Если override уже есть, добавьте env_file в существующий сервис client, сохранив остальные параметры. Поля environment из основного compose имеют приоритет над env_file: APP_NAME и Telegram-параметры из основного compose меняйте через его .env/секции environment.

Минимально сверьте:

```dotenv
PROXY_CATEGORY=proxy,vpn-mz,vpn-promo
PROXY_STORAGE_PREFIX=vpn_mrzb_
SHOW_PROXY_SUB_LINK=true
SHOW_PROXY_QR=true
```

Категория тарифа SHM должна совпадать с одним из PROXY_CATEGORY; префикс — с settings.storage_prefix и вашим основным шаблоном подписки. Применение клиентских переменных требует пересоздания клиента:

```sh
docker compose config --quiet
docker compose up -d --no-deps --force-recreate client
```

## 5. Проверьте результат на тестовом аккаунте

1. Откройте активную основную услугу → «Ваша подписка под контролем» → «Серверы тарифа». Должны появиться Москва и Франкфурт. Если осталось «не настроен», сравните именно service_id этой услуги с settings.tariff_ids, проверьте server_choice_enabled и версию API.
2. Выберите локацию, подтвердите действие и обновите подписку в приложении. В панели должны поменяться только группы переключаемого набора; отдельно купленная группа сохраняется.
3. Откройте «Расширения». Причины отсутствия SQL-журнала, безлимита, неправильного периода/UUID или запрещённого заказа теперь показаны в интерфейсе. Если список пуст — проверьте тарифные ID и addons_enabled.
4. Создайте один заказ без достаточного баланса: лимиты не должны увеличиться до оплаты. Оплатите через SHM, дождитесь успешного локального задания и проверьте фактический лимит панели. При достаточном балансе SHM может списать деньги сразу.
5. При ошибке выдачи проверьте журнал этого задания, исправьте настройку и повторите то же задание. Не покупайте повторно: повторное оформление создаёт отдельный оплачиваемый заказ.

HTTP-задержка из браузера требует отдельного публичного HTTPS /ping с корректным сертификатом и CORS на каждом сервере. По желанию добавьте ping_url к элементам main_values.monitor_nodes. Без него мониторинг может показать TCP-замер от биллинга; это не пинг с устройства клиента. Подробности: [мониторинг и config.main](main-config.md).

Реальные платежи, права токена и события вашей установки проверяются на стенде. Этот комплект — конфигурационный пример; реальные домены, токены, ID и UUID автоматически определить из репозитория нельзя.
