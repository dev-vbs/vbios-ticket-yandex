# Ответ поддержки: фотография с подписью в личный бот

## Как отвечает сотрудник

1. Откройте **тему нужного тикета** в закрытой группе поддержки Telegram.
2. Прикрепите фотографию и напишите пояснение **в поле подписи к этой фотографии**. Затем отправьте.
3. Пользователь увидит изображение и текст в кабинете, а также получит фотографию с той же подписью в личном чате с ботом. Для изображения, отправленного как файл, используется сообщение с документом и подписью.
4. На сообщении будет кнопка `↩️ Ответить · #номер`. Пользователь также может сделать обычный Telegram Reply прямо на фотографию и отправить текст или свою фотографию с подписью.

Не отправляйте текст и фотографию двумя разными сообщениями, если они должны выглядеть одним ответом. Telegram передаёт альбомы несколькими обновлениями: это не единое сообщение с общей подписью для всех файлов.

Поддерживаются JPEG, PNG, WebP, GIF до 5 МиБ. Пользователь должен заранее запустить **этого же бота**, связать его с аккаунтом кабинета и не блокировать его. Профиль бота должен совпадать с `config.ticket.telegram_profile`.

## Что изменено

Фото отправляется через `sendPhoto` по полученному этим ботом `file_id`; изображение-документ — через `sendDocument`. Не требуется сначала отправлять отдельное текстовое уведомление и затем копировать сообщение из группы. Сохраняются исходная подпись, её форматирование и привязка сообщения к тикету для обычного Reply.

Сохранение вложения в кабинете по-прежнему требует рабочего S3 и доступа сервера к загрузке файлов Telegram. Если используется Telegram API relay, нужен маршрут `/file/botTOKEN/...` наряду с `/botTOKEN/...`.

Если ответ сохранён, но доставить его в личный бот не удалось, в теме поддержки появится предупреждение. Исправьте привязку/доступность бота и отправьте ответ повторно; уже сохранённый ответ остаётся в кабинете. Автоматической повторной отправки ранее не доставленных ответов здесь нет.

## Обновление сервера

Дождитесь успешной сборки core в GitHub Actions. Для установки поверх версии с выбором ИИ/сотрудника новые таблицы не нужны. Если та версия ещё не устанавливалась, сначала выполните [миграцию из инструкции обновления](UPGRADE-TICKETS.md), включая `ticket-responder.sql`.

```bash
cd /opt/shm
docker compose pull core spool
docker compose up -d --no-deps --force-recreate core spool
docker compose logs --since=5m core spool
```

Команды предполагают, что текущий Compose использует `ghcr.io/dev-vbs/vbios-core:latest`. При закреплённых тегах/digest сначала укажите нужную новую версию. Для локальной сборки необходимо обновить исходники и пересобрать core.

Проверка: создайте тестовый тикет, ответьте в его теме фото с подписью, откройте кабинет и личный бот пользователя, затем ответьте через Reply на полученную фотографию. Сверьте текст, изображение и номер тикета в обоих направлениях. Автоматические проверки используют имитацию Telegram и базы; реальную доставку нужно проверить на вашей установке.
