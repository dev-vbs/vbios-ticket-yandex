# Настройка новой стартовой страницы

[Полный готовый шаблон config.main](main-config-template.txt) содержит тексты новой страницы, первый экран, визуальные шаги, возможности, преимущества, FAQ, заключительный блок и ваши три сервера Remnawave.

## Применение через local

1. Сохраните копию текущего `config.main`: шаблон заменяет объект `value` целиком.
2. Скопируйте весь файл `main-config-template.txt` в шаблон SHM и назначьте транспорт **`local`**. Это шаблон SHM, а не команда Linux.
3. Проверьте название, тексты, фактические возможности сервиса и UUID узлов. Выполните шаблон с правами изменения конфигурации.
4. Откройте `/shm/v1/system/main` и проверьте новые поля. Обновите `/login` и проверьте обе темы.

Для новой версии дизайна сначала дождитесь успешной сборки и публикации Docker-образа, затем:

```bash
cd /opt/shm
docker compose pull client core spool
docker compose up -d --no-deps --force-recreate client core spool
```

В этой версии обновляются клиент и разрешённые публичные поля API в `core`. Обновите также `spool`, использующий тот же серверный образ.

Последующие изменения только текстов `config.main` не требуют пересборки и перезапуска клиента.

## Поля страницы

| Поля | Назначение |
| --- | --- |
| `name`, `intro`, `title`, `accent_title`, `description` | Название и первый экран |
| `primary_button`, `login_button`, `secondary_button` | Основное действие, вход существующего пользователя, кнопка шапки |
| `compatibility` | Фактически поддерживаемые платформы |
| `visual_steps` | Полоса шагов под первым экраном (`title`) |
| `hero_cards` | Две иллюстрированные карточки первого экрана: `title` и `description`. Первая открывает AJAX-регистрацию/вход, вторая — `/status` |
| `catalog_title`, `catalog_description`, `catalog_button`, `catalog` | Возможности сервиса |
| `plans_title`, `plans_description`, `plan_button`, `plans` | Необязательная витрина тарифов |
| `geography_title`, `geography_description` | Заголовок и пояснение локаций |
| `benefits_title`, `benefits_description`, `benefits` | Преимущества |
| `connection_title`, `steps` | Порядок подключения |
| `faq_title`, `faq_description`, `faq` | Вопросы и ответы |
| `cta_title`, `cta_description` | Последний блок с призывом начать |
| `nav_benefits`, `nav_connection`, `nav_questions`, `support_label` | Подписи навигации и поддержки |
| `monitor_enabled`, `monitor_nodes` | Публичный мониторинг |

Элементы `catalog`, `visual_steps`, `benefits`, `steps`, `faq` содержат `title` и `description`. Ссылка поддержки и юридические документы используют существующие настройки клиента.

## Тарифы и оплата

### Автоматически из SHM (рекомендуется)

Внутри `config.main` укажите:

```text
plans_source = 'shm'
plans_currency = 'RUB'
plans = []
```

API `/shm/v1/system/main` заполняет `plans` из тарифных планов SHM: название (`name`), описание (`descr`), стоимость (`cost`) и период в месяцах (`period`). Для составных услуг учитывается стоимость дочерних услуг. Клиенту дополнительный запрос не нужен. Изменения тарифов видны после обновления страницы.

В административной части SHM включите у нужных тарифов «Разрешить заказ» (`allow_to_order = 1`). Удалённые тарифы и услуги, указанные в `config.remna.addons`, исключаются. Чтобы публиковать только определённые тарифы, добавьте их реальные ID:

```text
plan_service_ids = [ 6 7 8 ]
```

Без `plan_service_ids` показываются разрешённые к заказу тарифы (до 20 карточек из первых 100 записей). Пустой `plan_service_ids = []` скрывает все тарифы. Указание ID не обходит флаг разрешения заказа.

Публичная витрина показывает базовые цены без персональных скидок и бонусов. Валюта `plans_currency` — подпись, она не конвертирует цену. Пользовательские шаблоны прайс-листа `billing.price_list_template_id` здесь не выполняются: для публичной витрины задайте `plan_service_ids`. Доступность заказа и итоговую оплату SHM проверяет после входа. Описание показывается текстом, HTML не исполняется.

После установки новой серверной версии обновите `core` и `spool` командами выше. Далее менять тарифы можно в SHM без пересборки.

### Ручная витрина

Для ручного режима удалите `plans_source` или установите `plans_source = 'manual'`.

В ручном режиме `plans = []` скрывает витрину цен. Для включения добавьте свои реальные условия по структуре:

```text
plans = [
    {
        title = 'Название тарифа'
        price = 'Ваша реальная стоимость'
        description = 'Для кого этот тариф'
        details = 'Лимит устройств и срок действия'
    }
]
```

Это оформление витрины. Массив не создаёт услуги SHM и не меняет цену биллинга. Кнопка открывает существующую AJAX-авторизацию; выбор, покупка, продление, расширения и смена тарифа выполняются через SHM. Все условия должны соответствовать реально продаваемым услугам.

## Ваш мониторинг

В шаблоне сохранены предоставленные UUID: `903ed586-8232-49bd-9282-c5f06e260a3e`, `2925b673-5301-4709-874f-bf45801d2ed5`, `9debc8a1-e409-4c38-bbbf-5aeb1187fe20`. Две Москвы подписаны «Москва · 1» и «Москва · 2», чтобы их можно было различить. Проверьте соответствие UUID вашей панели.

Для работы API должен быть настроен `config.remna` с URL и токеном панели. TCP-замер использует адрес и порт узла. При необходимости добавьте `ping_ip` и `ping_port`. Для браузерной проверки добавьте `ping_url = 'https://your-node.example/ping'` с корректным сертификатом и CORS; не подставляйте случайный IP или чужой адрес.

✅ свежий успешный замер — зелёный; ❌ `offline` — красный; ⚪ нет замера или данные устарели — серый; 🛠️ `maintenance` — техработы. У числа указан источник задержки. [Подробнее о мониторинге](MONITORING.md).

`config.main` публично доступен без авторизации. Не добавляйте в него токены, пароли, ключи подписки и приватные ссылки. Токен панели хранится в `config.remna`. Визуальный блок объясняет сценарий использования и не изображает вымышленные данные аккаунта.

## Первый экран с контурной графикой

Новый Login использует компактную шапку, крупный заголовок и две карточки с SVG-графикой. Первая открывает существующую AJAX-регистрацию (или вход, если регистрация отключена), вторая ведёт на публичную страницу `/status`. Тексты карточек задаёт `hero_cards`: первые два элемента с `title` и `description`. Если массив не задан, используются встроенные подписи.

Чтобы обновить только заголовок и две карточки, сохранив тарифы, мониторинг и остальные настройки, выполните [небольшой шаблон через local](login-design-local.txt). Полный `main-config-template.txt` заменяет объект целиком; для обновления существующей установки предпочтительнее этот небольшой шаблон. Новые карточки работают и без изменения конфига.

`visual_steps[].title` теперь используется в полосе шагов под первым экраном. Поля `preview_label`, `preview_title`, `visual_caption` относятся к прежнему варианту иллюстрации и на новом первом экране не используются. Светлая и тёмная темы используют общую структуру; переключатель и настройки AJAX-формы сохранены.
