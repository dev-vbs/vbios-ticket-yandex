# Обновление тикетов: изображения и выбор ответившего

Применяется к существующей установке этого репозитория. Сначала сохраните `.env`, Compose, `/app/data`, дамп MySQL и копию бакета. Проверьте обновление на тестовой базе. Не запускайте `down -v` и не меняйте версию `_shm` ради миграции.

## 1. Получите исходники

```bash
cd /opt/vbios-source
git pull --ff-only
cd /opt/shm
```

Если исходники находятся в другом каталоге, замените путь. При локальных изменениях сначала разберите конфликт: не применяйте `reset --hard` к рабочему проекту.

## 2. Добавьте таблицу выбора сотрудника / ИИ

Примените **до запуска нового core и spool**:

```bash
cd /opt/shm
docker compose stop core spool
docker compose cp /opt/vbios-source/server/app/sql/ticket-responder.sql mysql:/tmp/ticket-responder.sql
docker compose exec mysql mysql -u root -p webface -e 'SOURCE /tmp/ticket-responder.sql; SHOW COLUMNS FROM ticket_preferences;'
```

Введите действующий root-пароль базы. Если имя БД другое, замените `webface`. SQL создаёт только новую таблицу и не удаляет обращения. Старые тикеты не получают принудительный выбор: их прежнее поведение сохраняется до переключения.

Если дополнительных таблиц тикетов ещё нет, сначала примените `ticket-3.7.0.sql` и `ticket-telegram-images.sql` по инструкции первичной установки. При произвольной старой схеме сначала проверьте совместимость, а не рассчитывайте на `CREATE TABLE IF NOT EXISTS`.

## 3. Обновите образы

Дождитесь успешной сборки всех задач GitHub Actions. В `/opt/shm/.env` проверьте:

```dotenv
SHM_REPO=ghcr.io/dev-vbs
CORE_VERSION=latest
CLIENT_VERSION=ghcr.io/dev-vbs/vbios-clients:latest
```

Актуальный workflow собирает **vbios-clients**, старый vbios-client больше им не обновляется. Сохраните остальные настройки `.env`, особенно пароли БД и ключи S3.

```bash
cd /opt/shm
docker compose pull core spool api client
docker compose up -d --no-deps --force-recreate core spool api client
docker compose ps
docker compose logs --since=5m core spool api
```

`api` нужно обновить вместе с core и кабинетом. Если образы по `latest` ещё не собраны, pull вернёт предыдущую сборку. Для контролируемого развёртывания используйте согласованные теги/digest.

## 4. Настройки

Новые ключи облака не требуются. Бакет остаётся приватным, права на чтение объектов у сервисного аккаунта должны сохраняться. Для отображения картинки по подписанному URL через img CORS не требуется. Если в собственном Nginx задан Content-Security-Policy, разрешите `img-src` для используемого HTTPS-хоста Yandex Object Storage и `blob:`.

Чтобы предложить ИИ в кабинете, в `config.ticket.ai` нужны `enabled: true`, `reply_mode: "auto"`, рабочий ключ и модель. Для сотрудника сохраняются существующие `ticket.id`, `telegram_profile` и права бота в группе. Неработающий ИИ не переводит тикет сотруднику автоматически: пользователь выбирает сотрудника в обращении.

## 5. Проверка

1. Откройте кабинет после обновления страницы. В новом тикете должен появиться выбор ИИ/сотрудника; недоступный ИИ выключен.
2. Создайте обращение сотруднику с фото и текстом. Проверьте кабинет, тему Telegram и обратный ответ с фото.
3. Если ИИ включён, создайте отдельный тикет ИИ; группа не должна получать его сообщения до передачи сотруднику.
4. Передайте тикет сотруднику. Проверьте контекст в группе и отсутствие последующих ответов ИИ.
5. Откройте несколько больших изображений. В запросах браузера должны появиться временные URL Object Storage вместо больших ответов base64. Если прямой доступ недоступен, сработает резервная загрузка через SHM. Проверьте повторную попытку при кратком отключении сети.
6. Войдите другим клиентом: API не должен выдавать ему ссылки на чужие вложения.

Подписанные ссылки действуют 15 минут и являются временным доступом к конкретному файлу; не отправляйте их в публичные чаты. Удаление доступа к аккаунту не отзывает уже выданную ссылку до истечения её срока.

При ошибке не удаляйте историю и таблицы. Верните согласованные предыдущие образы; дополнительную таблицу можно оставить. Сохраните журнал без токенов и проверьте SQL, реальные версии образов и доступ к бакету.
