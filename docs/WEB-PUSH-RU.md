# Push-уведомления: iOS, Android и компьютер

Используется стандарт Web Push с собственным сервисом `push` и ключами VAPID. Регистрация в Firebase или платная подписка не нужны. Требуется публичный HTTPS-адрес кабинета.

Подготовить сервер: [основная установка](INSTALLATION-RU.md). Справка платформ: [Apple Web Push](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers), [MDN Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API).

## 1. Ключи

Из корня проекта, на сервере с Docker:

```bash
docker compose pull push
docker compose run --rm --no-deps push node --input-type=module -e "import webpush from 'web-push'; console.log(webpush.generateVAPIDKeys())"
openssl rand -hex 32
```

Первая команда генерации выводит `publicKey` и `privateKey`. Последняя команда генерирует отдельный внутренний токен. Запишите в `.env`:

```ini
WEB_PUSH_ENABLE=true
PUSH_PUBLIC_ORIGIN=https://bill.example.com
VAPID_SUBJECT=mailto:admin@example.com
VAPID_PUBLIC_KEY=ПУБЛИЧНЫЙ_КЛЮЧ
VAPID_PRIVATE_KEY=ПРИВАТНЫЙ_КЛЮЧ
PUSH_INTERNAL_TOKEN=СЛУЧАЙНЫЙ_ТОКЕН_ИЗ_OPENSSL
```

Укажите origin без завершающего `/` и без пути. Приватный ключ и внутренний токен не должны попадать в `config.main` или frontend. Не меняйте VAPID-ключи при каждом обновлении: существующим устройствам потребуется переподписка.

## 2. Применение

```bash
docker compose pull push client core api spool
docker compose up -d push client core api spool
docker compose ps push
docker compose logs --tail=50 push
```

Внешний Nginx должен передавать `/push/` в контейнер client, как остальные пути кабинета. Внутренний `/internal/send` наружу не публикуется. Сервис проверяет сессию пользователя через SHM; пользователю доступны только его подписки. Серверу нужен исходящий HTTPS-доступ к push-провайдерам браузеров.

## 3. Подключение пользователем

Войдите в кабинет → «Профиль» или «Уведомления» → «Уведомления на устройство» → включите их и подтвердите разрешение браузера. Затем нажмите тестовую отправку.

- **iPhone/iPad:** iOS/iPadOS 16.4+, Safari → «Поделиться» → «На экран Домой». Откройте установленную веб-версию и включите уведомления внутри неё. Обычная вкладка Safari не заменяет этот шаг.
- **Android:** поддерживаемый браузер, например Chrome; разрешите уведомления сайта и браузера в настройках ОС.
- **PC/macOS:** поддерживаемый браузер с разрешёнными системными уведомлениями. Режим «Не беспокоить» может скрывать сообщения.

Разрешение запрашивается только по нажатию пользователя. На общем устройстве выключите уведомления перед выходом. Подписка устройства сохраняется между сессиями; выход из кабинета сам по себе не отменяет её.

## 4. Отправка из SHM

Сохраните шаблон с транспортом **local**. Это Template Toolkit, не Bash. Выполняйте в контексте пользователя-получателя:

```text
{{ result = user.srv('Push').send(
    title = 'vBios — уведомление'
    body = 'В кабинете появилась новая информация.'
    url = '/notifications'
    tag = 'account-update'
) }}
```

Вызов другого `user_id` разрешён только администратору. Назначайте шаблон нужному событию в вашей конфигурации событий SHM: например, ответ поддержки или напоминание о продлении. **Автоматическая отправка на все события не включена:** настройте конкретные триггеры и защиту от повторов в SHM. Не отправляйте пароли, ключи или ссылки подписки в тексте уведомлений.

Сервис возвращает `sent`, `expired`, `failed`. `sent` означает принятие push-провайдером, а не доказанную доставку на экран. Истёкшие подписки (404/410) удаляются. Нет подписанных устройств — отправлено 0. При большом количестве устройств отправка ограничена 20 устройствами на пользователя.

## Резервная копия

Ключи `.env` и том `push-data` храните в защищённой резервной копии. Для согласованной файловой копии SQLite остановите `push`, сохраните том целиком (включая WAL/SHM, если они есть), затем запустите сервис. Не используйте `docker compose down -v`: это удалит данные проекта.

## Если не приходит

Проверьте `/push/config` на домене кабинета (публичный ответ содержит только enabled/publicKey), состояние контейнера, действующий вход, разрешения ОС и браузера. При ошибке origin проверьте `PUSH_PUBLIC_ORIGIN`. При запрете браузером разрешите сайт вручную. После смены ключей выключите/включите подписку на каждом устройстве. На iOS проверьте запуск именно с экрана Домой. Тест на сервере не заменяет проверку на реальном устройстве.
